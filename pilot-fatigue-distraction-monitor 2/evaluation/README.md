# Evaluation framework

## `synthetic_demo.py` -- the 4-pilot showcase

```bash
uv run pilot-monitor-demo
```

Generates four synthetic pilots with different personal baselines (see the
module docstring), runs Model 1 (fixed threshold), Model 2 (personal
statistics), and Model 3 (personal statistics + GRU temporal anomaly model,
if PyTorch is installed) against each, and writes:

- `results/comparison.json` -- full per-pilot, per-pathway metrics
- `results/comparison.png` -- summary chart
- `results/REPORT.md` -- a written report, including a "Discussion" section
  computed from the actual numbers each run produces (not a fixed template)

**Read the top of `synthetic_demo.py` and the top of `REPORT.md` before
citing any number it produces.** This is synthetic, programmatically
labeled data, not real pilot recordings -- see the design document's Part
11 for why real pilot or driver data was not substituted silently. It
demonstrates that the full pipeline and comparison methodology work end to
end; it is not evidence of real-world accuracy.

## Running the real 4-person showcase

Once you have four consenting people you can record (colleagues, classmates
-- they do not need to be actual pilots for a computer-vision prototype
demo, but say so explicitly if they aren't):

1. `uv run pilot-monitor-calibrate --pilot-id <name> --duration 90` for each
   person -- a short webcam recording of ordinary, alert behaviour.
2. `uv run pilot-monitor --pilot-id <name> --log-path logs/<name>.csv` to
   record a live monitored session (or `--video` to replay a pre-recorded
   one) with full structured logging.
3. Load the CSVs and compute the same metrics as `synthetic_demo.py` using
   `evaluation/metrics.py`, against whatever ground truth you can establish
   for that session (e.g. a second observer's timestamped notes on when the
   person deliberately looked away or feigned drowsiness).

This is the difference the design document (Part 17-18) is explicit about:
a synthetic or self-recorded demo shows the system runs and can be
evaluated; it is not a substitute for labeled pilot data, and no report
generated by this code claims otherwise.

## `metrics.py`

Dependency-free precision/recall/F1/false-positive-rate/false-negative-rate
and alert-flap-rate computation, used by both the synthetic demo and (if you
extend it) a real-data evaluation run. `None` values in either the
predictions or the ground truth are excluded from the count rather than
treated as a class, which matters once ``DATA_INVALID`` frames are in the
mix.
